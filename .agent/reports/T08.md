## Rulings
- Result shapes: SIM `{ok,mode,status:'ok',latencyMs:270,response}`; REPLAY status exact|nearest (recorded latencyMs) | unrecorded (emulator, 270); LIVE ok → status 'ok'.
- LIVE failure: circuit ask → `ok:true, status fallback:<code>, response: emulator, error`. neuron ask → `ok:false, status error:<code>`, no response. budget_exhausted → `ok:false status error:budget_exhausted` (both kinds), mode → SIMULATED + warn banner.
- skip (in-flight, or circuit tick < liveMinIntervalMs wall): `{ok:false,status:'skipped'}`, `client.skipped++`, no events, no budget. min-interval gate applies to circuit only.
- aborted: result status 'aborted' ok:false; emits `jev:error` code aborted, NOT `jev:response`.
- Events emitted by client: jev:request (all modes), jev:response, jev:error, banner, mode:changed (only on internal switch to SIMULATED; header's own setMode emits nothing).
- Health race: `setMode()` bumps selection token; `health()` returns null if token changed during flight. T15 must call setMode('LIVE') BEFORE health(), setMode(other) on switch-away. health() sets keySource (null on fail); X-JEV-Key sent only when keySource === 'none'.
- proxy_unreachable: client does NOT re-run health itself; T15 reacts to jev:error / banner.
- 3 consecutive failed LIVE ticks (any code, incl. timeout/malformed) → SIMULATED + error banner. resetRun zeroes the counter.
- Retry-After: `retry-after-ms` preferred, else `retry-after` s; >10 s → no retry; else max(delay, RA). Budget checked + incremented per attempt.
- Replay path validates entry.response with validateResponse (FR-REC-05); invalid → unrecorded.
- Scheduler: stimulus-change tick and grid ticks both gated by `autoJev`. Debounce ruling: change <300 ms after previous change moves a still-pending tick to latest+50; if previous tick already fired, adds none (grid tick catches up) → satisfies U-56 "100 ms apart → one change tick". After a change tick fires, next grid tick skipped iff < 300 ms later.
- Scheduler applies control via `sim.setControl(applyControl(...))` immediately on answer (sync: in effect next step; async LIVE: on arrival, effect next step). Stale async (after reset) ignored. `jevControl` off → neutral setControl on next afterStep. applyControl: missing question answers → neutral (β 0 / M 1). Novelty flash (ν > 0.7) NOT done here → T15 via jev:response.
- scheduler.reset() also calls client.resetRun() (callIndex 0, abort in-flight).
- Tick window summary uses sim.n/sim.t, so afterStep(n) must be called right after sim.step() (n = index of step just run).
