# R3 — JEV (TypeSafe) API facts for static github.io browser demo

Date: 2026-10-17. Key: `TYPESAFE_API_KEY` env, never printed/written. Test keys in probes were fake/redacted.

## VERDICT
- **Browser on github.io CANNOT call JEV directly.** CORS blocks it.
  - Preflight `OPTIONS` with `Origin` returns **HTTP 400** body `Disallowed CORS origin` for every origin tested: `https://example.github.io`, `https://octocat.github.io`, `null`, `https://api.typesafe.ai`, `https://evil.example`.
  - Preflight response allow-list (`Access-Control-Allow-Headers`) is present, but `Access-Control-Allow-Origin` is never returned for any tested origin.
  - Real POST with `Origin: https://example.github.io` → HTTP 200 but **no `Access-Control-Allow-Origin` header** in response (only `access-control-allow-credentials: true`, `access-control-expose-headers: Retry-After, retry-after-ms`). Browser `fetch` will reject reading the response.
  - Conclusion: origin allow-list is server-side, closed to github.io. Not fixable client-side. Requires a proxy you control.
- Non-browser callers (curl, Python, Node) work fine. No Origin = no CORS check.

### Endpoint
- `POST https://api.typesafe.ai/v1/systemone`
- Headers: `Authorization: Bearer <API_KEY>`, `Content-Type: application/json`. Optional `Content-Encoding: gzip|x-gzip|zstd` (one layer only).
- Keys: https://console.typesafe.ai/keys

### Request
```json
{
  "state": "<string | object | array>",
  "model": "jev-latest",
  "questions": {
    "<your_key>": {"type":"noul","instructions":"..."},
    "<your_key>": {"type":"choice","instructions":"...","criteria":{"opt":"desc"}},
    "<your_key>": {"type":"score","instructions":"...","criteria":["level0","level1","level2"]}
  }
}
```
- `state`: required. string|object|array. Text only (no images in state per concepts page; images doc exists).
- `questions`: map of your keys → question. Keys not sent to model; answers returned under same keys.
- noul: `type`, `instructions` required; `criteria` optional `{true: ..., false: ...}`.
- choice: `criteria` map option→desc (or null). **Max 255 options.**
- score: `criteria` **ordered array**, **min 2, max 10 levels**. Dict criteria → 422.
- `instructions`: string|object|array.
- Limits: body ≤ 32 MiB; UTF-8 JSON no BOM; nesting ≤ 64; numbers finite only.
- Max questions per request: NOT documented.

### Response (real, redacted req ids kept)
```json
{"model":"jev-1.13.0","answers":{"n1":{"type":"noul","noul":0.99},"c1":{"type":"choice","choice":"technical","confidence":1.0,"probabilities":{"billing":0.0,"technical":1.0,"sales":0.0}},"s1":{"type":"score","score":0.66,"confidence":0.49,"legend":{"0":"Calm, just stating facts","1":"Frustrated but civil","2":"Very angry, strong language"},"probabilities":{"0":0.34,"1":0.66,"2":0.0}}},"usage":{"input_tokens":428,"output_tokens":71}}
```
- Answer fields: noul → `noul` (0–1). choice → `choice`, `probabilities` (sum 1), `confidence`. score → `score` (prob-weighted, can be fractional), `legend`, `probabilities` (keys "0".."N"), `confidence`.
- Score confidence: 1.0 when all mass on one level; lower as spread. Formula not published. Describes answer, not correctness.
- **Score IS supported** (primitive exists).

### Models
- `jev-latest` → jev-1.13.0 (stable). Used in all examples.
- `jev-1.13.0` current. `jev-1.14.0` available from 2026-10-14 (newest). `jev-preview` → 1.14.0.
- Response `model` field reports the concrete version (`jev-1.13.0` observed today).

### Pricing
- $42 per Btok ($0.042 per Mtok), **input tokens only; output free**. Source: models.md.
- Per call ~428 input tokens for 3-question probe → ≈ $0.000018/call (≈ $0.00002). Negligible for demo.
- No per-call/credit pricing listed.

### Rate limits
- Per organization, tokens/s and requests/s. Exceed → 429. Exact numbers: in developer console only (not in docs). No rate-limit headers documented.
- `Retry-After` / `retry-after-ms` are in `access-control-expose-headers` (suggests they exist), not documented as semantic.

### Errors (docs + probes)
| Status | Meaning | Probe body (verbatim) |
|---|---|---|
| 400 | rule violation / max_tokens_exceeded | `{"detail":{"error_type":"api_usage_error","message":"Invalid request."}}` (bad question type "bogus") |
| 401 | bad key | `{"detail":{"error_type":"authentication_error","message":"Cannot authenticate with the server. Please check your API key and try again."}}` |
| 403 | no Authorization header | `{"detail":{"error_type":"authentication_error","message":"Must supply an API key! Check your request and try again."}}` |
| 413 | body >32 MiB | docs only |
| 415 | bad Content-Encoding | docs only |
| 422 | validation | malformed JSON → `{"detail":[{"type":"json_invalid","loc":["body",28],"msg":"JSON decode error","input":{},"ctx":{"error":"Expecting value"}}]}`; dict score criteria → `{"detail":[{"type":"list_type","loc":["body","questions","q","score","criteria"],"msg":"Input should be a valid list","input":{"a":"b","c":"d"}}]}` |
| 429 | rate limit | docs: back off + retry (client already does) |
| 529 | overloaded | docs: retry w/ backoff |
Note: client's `jev_client.py` expects `answers` in 200 body only; 4xx bodies are not parsed (only code used).

## 4. Options for github.io demo (not verified by build, list only)
1. **Cloudflare Worker proxy** (free tier): `fetch("https://api.typesafe.ai/v1/systemone", {headers:{Authorization: env-less passthrough of user key, ...}})` + add `Access-Control-Allow-Origin: https://<user>.github.io`. Worker sees user key in transit (no storage). Must be deployed by user.
2. **User-run local proxy** (Python stdlib http.server / Node) on `http://localhost:<port>`, forwards to api.typesafe.ai, adds ACAO. Browsers allow localhost fetch from https origin only if server sends ACAO; mixed content not an issue for localhost in modern browsers (verify per browser).
3. **Direct call with user-pasted key**: NOT possible — CORS fails. Key would also be exposed in page.
4. Hybrid: static page shows precomputed/recorded JEV responses (no key) for offline demo.
